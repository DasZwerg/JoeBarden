v3.3.4

Summary: Improved playback efficiency, queue reliability, playlist safety, command access controls, and YouTube authentication maintenance.

🔧 BUG FIXES
- Dependencies: added the missing OpenAI SDK required by the optional Groq fallback.
- AI fallback: Gemini quota errors now use Groq when a Groq API key is configured.
- Startup: cog registration and Gemini validation now run once instead of after every reconnect.
- Windows: console output no longer crashes when the active encoding cannot display an emoji.

⚡ PERFORMANCE & RELIABILITY
- Queueing: queued tracks now store metadata without starting unused FFmpeg processes.
- Playlists: playlist entries stay lightweight and are fully resolved only when playback begins.
- Playback: fresh stream metadata is applied immediately before creating the single FFmpeg process.
- Reverse: limited to known tracks of 15 minutes or less to prevent unbounded buffering.

🔒 DATA & ACCESS
- Playlists: saved playlists are now isolated per Discord server.
- Playlist storage: writes are locked and atomically replaced to prevent corruption or lost updates.
- Playlist storage: existing user-based data migrates automatically when first accessed.
- Commands: music-channel restrictions are applied consistently when MUSIC_CHANNEL_ID is set.
- Voice controls: users must join the bot's active voice channel before controlling playback.

🔑 YOUTUBE AUTH & POT
- Cookies: added a local command that validates and atomically installs YouTube cookie exports.
- Cookies: each extraction reloads current cookie state, so replacement no longer requires a bot restart.
- POT provider: added explicit configurable bgutil HTTP provider integration with the mweb client preferred.
- Health: added local and bot-owner-only checks for cookie, plugin, and provider status.
- Monitoring: hourly checks validate managed cookies, retry provider failures three times, and report persistent outages to the bot owner.
- Diagnostics: startup confirms the number of validated YouTube cookie entries and keeps full provider connection failures in errors.txt.
- Error reporting: operational failures send sanitized, rate-limited owner DMs while details remain in errors.txt.
- Security: provider URLs cannot contain embedded credentials, browser databases are not read automatically, and Docker binds to loopback only.

🧪 TESTING
- Added focused tests for queue metadata, FFmpeg filters, reverse limits, playlist storage, AI fallback, cookie replacement, POT configuration, and safe owner notifications.
